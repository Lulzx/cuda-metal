# Versioned driver API names (#230), passed to ld64 as -alias_list.
#
# NVIDIA's libcuda exports these entry points under their _v2 names (cuda.h
# #defines the plain spelling to the _v2 one), so programs that resolve the
# driver with dlopen/dlsym, or link against an alias libcuda, look the _v2
# names up. CuMetal's unsuffixed implementations already have the _v2 ABI:
# 64-bit CUdeviceptr, size_t sizes and pitches, and the size_t-based
# CUDA_MEMCPY2D / CUDA_MEMCPY3D / CUDA_ARRAY3D_DESCRIPTOR layouts. Each line
# makes the second symbol an alias at the same address as the first.
#
# Only names whose signature matches NVIDIA's _v2 export are listed:
#   cuGraphInstantiate_v2 is CUDA 11's 5-argument form (error node + log).
# cuGetProcAddress is not here: its unsuffixed export keeps the original
# 4-argument ABI and cuGetProcAddress_v2 is a separate 5-argument function
# (runtime/driver/cuda_driver.cpp).
# Not aliased: cuCtxCreate_v3/_v4 (extra affinity/params arguments), and
# entry points CuMetal does not implement (cuMemHostRegister, cuArrayCreate,
# cuMemcpy2DUnaligned, cuStreamBeginCapture, ...).
#
# tests/functional/driver_v2_symbols_test.cpp checks every alias resolves to
# the same address as its unsuffixed function.

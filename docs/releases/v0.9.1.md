# CuMetal v0.9.1

[Release index](README.md)

CuMetal 0.9.1 fixes the installed toolchain. In 0.9.0 (and earlier), the
device pass of an installed `cumetalc` looked for `cuda_runtime.h` in the
build's source tree. Homebrew deletes that tree after installing, so
`cumetalc` from `brew install lulzx/tap/cumetal` could not compile any kernel.
It now reads the headers from the installed `include/` directory, like the
rest of the toolchain. Everything else is as in
[v0.9.0](v0.9.0.md).

## Verification

On Apple M4 Pro, macOS 27.2.1: `functional_installed_cumetalc_link_executable`
poisons the installed `cuda_runtime.h` for device code and requires the compile
to fail on it; the test fails against the 0.9.0 `cumetalc`. An installed
prefix with the source tree's `runtime/api` moved away compiles and runs a
Cuport-Matrix probe.

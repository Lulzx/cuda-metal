# Full vanity-miner PTX compilation inventory

Historical baseline at consumer commit `210939b`. The subsequent
[initialized-data selection change](ptx-initializer-selection.md) unblocks
and numerically verifies the full-module launch probe; the counts below have
not been replaced with an unmeasured post-fix inventory.

This baseline measures strict typed PTX-to-MSL emission only. It does not
measure Apple's MSL compilation, runtime loading, numerical GPU correctness,
or mining throughput. See the [per-entry JSON report](vanity-miner-ptx-inventory.json)
for all entry names and first failures.

## Results

| Outcome | Entries |
| --- | ---: |
| Attempted independently | 123 / 123 |

| Compile failure: shared initialized-global declaration | 123 |
| Timeout / process crash | 0 |

All four mining entries and all 119 test entries exit with code 1 at the same
module-level declaration. This is one shared first blocker, not evidence of
123 distinct unsupported kernels. Input checksum and the complete entry-name
set were checked against the producer's manifest.

  `36ca4ed2be0cb16e6028f8ebd74deffd07500adc`.
- [Artifact build](https://github.com/brandonros/vanity-miner-rs/actions/runs/34774932262),
  artifact `vanity-miner-x86_64`, file `output.ptx`.
- PTX 9.2, `sm_89`, generated by CUDA 13.2 / NVVM 7.0.1.
- PTX SHA-256: `41db05e2e1b6281923b9d9f8f157ced57f69a9a9e9d794d0513db6e618bbb6d7`.
- Consumer compiler source: CuMetal commit
  `210939b` on `poc/rust-ptx-harness`; the JSON records the executable checksum.
- Host: Apple M5, 2026-09-13. Release PTX-only build, binary shim disabled.
- No PTX instructions, globals, helpers, or target headers were rewritten or
  removed. Each invocation receives the complete 25,087,361-byte module.

```sh
gh run download 34774932262 --repo brandonros/vanity-miner-rs \
  --name vanity-miner-x86_64 --dir /tmp/miner-artifact
(cd /tmp/miner-artifact && shasum -a 256 -c SHA256SUMS)
python3 demos/rust-ptx/inventory.py /tmp/miner-artifact/output.ptx \
  --compiler build-rust-ptx-apple/cumetalc --out /tmp/miner-inventory \
  --jobs 8 --timeout 180
```

The compiler flags are `--backend=cumetal-ir --ptx-strict --overwrite
--entry ENTRY --emit=msl`. Workload specializations are disabled. Each invocation
has a 180-second limit; a pass requires both emitted MSL and an ABI sidecar.
The compact committed JSON deduplicates diagnostics; the tool's full report,
per-entry compiler logs, and any emitted files remain in the output directory.

## Shared first blocker

The initialized-global scanner rejects an Ed25519 table alias declared as
`.global .align 8 .u8 ...ED25519_BASEPOINT_TABLE[8] = {...}`. The initializer
contains address-byte expressions such as `0xFF(table_symbol)`. This scan
runs before entry selection and before filtering globals by use, so even the
launch probe is blocked before its instructions are lowered.

Small independent probes confirm two distinct limitations:

| Unused initialized global beside an empty kernel | Typed MSL emission |
| --- | --- |
| `.b8 alias[8] = {0,0,0,0,0,0,0,0}` | Pass |
| `.u8 alias[8] = {0,0,0,0,0,0,0,0}` | Reject: unsupported declaration |
| `.b8 alias[8] = {0xFF(table),0,0,0,0,0,0,0}` | Reject: non-byte element |

## Next bounded task

Move unsupported-initializer validation behind selected-entry/helper/global
reachability, preserving failures when unsupported data is actually required.
Add positive coverage for an unrelated initialized global and negative coverage
for direct and transitive uses. Then rerun this same artifact and inventory to
expose the next real kernel-specific gaps. Kernels that use the Ed25519 alias
will still need address-relocation support before numerical testing.

A first-failure inventory cannot enumerate every unsupported operation hidden
behind the first diagnostic. The final compatibility target remains four
mining kernels plus 119 test kernels, each with separate numerical validation.
